# رفع اشکال

## CSS بارگذاری نمی‌شود

Document Root را روی `frontend/web` قرار دهید، `npm run build` را اجرا کنید و دسترسی نوشتن asset/runtime را بررسی کنید. فایل `frontend/web/css/app.css` خروجی build از `src/app.css` است؛ هرگز `app.css` را دستی ویرایش نکنید. در وب‌سرور داخلی از فرمان README استفاده کنید.

## اتصال دیتابیس برقرار نیست

مقادیر `DB_HOST`، `DB_PORT`، `DB_NAME` و مجوز کاربر را در `.env` بررسی و `php yii install/check` را اجرا کنید. برای MySQL داخل Docker معمولاً `127.0.0.1` از داخل container به میزبان اشاره نمی‌کند.

## migration اجرا نمی‌شود

ابتدا `php yii migrate/history` و متن کامل خطا را ببینید. migration اجراشده را ویرایش نکنید. در صورت نصب آزمایشی می‌توان از `composer test:install` برای بازتولید خطا روی دیتابیس خالی استفاده کرد.

## تصاویر نمایش داده نمی‌شوند

وجود فایل، URL ذخیره‌شده، Document Root و permission پوشه را بررسی کنید. داده‌های نمونه با `php yii seed` به assetهای موجود در `frontend/web/img/portfolio` متصل می‌شوند.

## اعلان‌ها کم نمی‌شوند

بازکردن جزئیات پیام، درخواست خدمات یا درخواست همکاری وضعیت آن را خوانده‌شده می‌کند. اگر ستون `read_at` موجود نیست، migrationهای جدید را اجرا کنید.

## خطای 403 در Installer

این رفتار پس از نصب طبیعی و ناشی از `.install.lock` است. برای نصب مجدد ابتدا backup بگیرید و [راهنمای نصب](installation.md) را بخوانید.

## Installer در مرحله migration متوقف می‌شود

اگر Apache ویندوز خطای `AH02965` ثبت می‌کند، وب‌سرور به‌جای PHP CLI اجرا شده است. نسخه جدید Installer مسیر `php.exe` را جداگانه تشخیص می‌دهد. در نصب‌هایی که PHP وب و CLI مسیر متفاوت دارند، `PHP_CLI_BINARY` را به مسیر کامل `php.exe` تنظیم و مرحله را دوباره اجرا کنید. جدول‌هایی که پیش‌تر ساخته شده‌اند مانع retry امن migration نمی‌شوند.

هنگام گزارش مشکل، نسخه PHP، سیستم‌عامل، مرحله بازتولید و بخش غیرحساس log را ضمیمه کنید؛ رمزها و اطلاعات کاربران را حذف کنید.
